# Atomic Persistence

Milestone: `pr_play_object_marking_mutation`. Date: 2026-11-09.

Previous save_character -> _save_json -> Path.write_text directly truncated character.json; bootstrap used _load_json direct writes. Snapshots already used _atomic_save_json/_atomic_write_bytes (same-directory nonexclusive temp, file fsync, os.replace, swallowed directory-sync errors). Existing runtime_commit_scope restores original bytes on Python exceptions, best effort with direct-write fallback, not a crash transaction. Identity calls this writer within that scope.

Reused the existing atomic primitive. All character JSON saves/bootstrap now dispatch through _save_json to _atomic_save_json; snapshot restore already uses the same primitive. JSON indent=2/UTF-8/schema preserved. Serialization finishes before temp creation; regular non-symlink destinations only; exclusive mkstemp in destination directory; permission bits copied; write/flush/fsync/close then bounded existing Windows rename retry. Successful os.replace is the visibility commit boundary. _sync_directory returns actual boolean support/success; OS failure after replacement is reduced durability, not an old-file assertion. Temporary read-only flags are removed for Windows cleanup on failure. Temp names do not end in .json.

Failure injection: serialization, temp creation, partial write, flush, file sync and replace all preserve exact prior hash, reload and remove temps. Directory open/sync errors after replacement retain new committed bytes and report false sync. Permission preservation and successful reload are tested. See atomic_save_traces.json, atomic_failure_*.json, verified_marking_junit.xml.

Single authoritative character inventory and single-process ordered turn lane; no multi-process lost-update protection, multi-file crash transaction or global exactly-once across timeline rollback. File fsync is required; directory sync is best effort and unavailable on this Windows host. Permission bits are preserved; custom Windows ACLs, ownership and inode metadata are not portably copied by the standard-library writer. Read-only Get-Acl audit confirmed current character.json has zero explicit access rules and inherited directory ACLs (permission_audit.json); no custom-file-ACL durability/security guarantee. Authorization/evidence are trusted internal caller assertions, not gameplay adjudication or a public authentication boundary. No conversational marking, inspection/removal, equipment/material inference or T06 completion.
