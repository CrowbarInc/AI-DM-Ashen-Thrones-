# Authority Integration

Milestone: `pr_play_object_visibility_authoring`. Date: 2026-11-09.

Internal entry `game.api.set_marking_visibility(request, authorization=grant)` reuses the existing marking coordinator. Pure `game.object_marking.prepare_visibility` requires the same private typed _VisibilityAuthorization. Trusted `_establish_visibility_authorization` validates request shape and binds canonical digest covering campaign/character, object, mark, operation, classification/scope, expected revision, request identity and structured evidence. Request authorization requires caller_id, decision_id, mechanics=not_applicable and positive bounded evidence refs for target_exists, marking_exists, rights, classification_basis, capability. These are upstream assertions, not physical checks or authentication. JSON authorized=true and serialized grants refuse. All binding mismatch cases tested. No new grant issuer endpoint exists.

API validates campaign from authoritative session and character/object from saved character, enters existing ordered_turn without in-memory request cache, holds existing persistence guard, checks WORLD_STATE ownership, stages detached candidate, and saves under runtime_commit_scope. No second state owner/database. Existing whole-character replacement route calls _client_visibility_unchanged and rejects introduction/change/removal/rebinding/duplication of classified bindings. Compare/save holds the same ordered_turn lane and persistence guard as classification, preventing a stale client replacement from erasing concurrent metadata. The two-thread blocking control verifies this serialization. Unchanged metadata and inventory reordering remain compatible. Trusted direct storage and historical snapshot restore retain their established roles; this is a local application, not a new authentication boundary.
