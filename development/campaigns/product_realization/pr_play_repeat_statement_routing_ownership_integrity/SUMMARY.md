# Statement-repetition routing ownership

**B/PARTIAL.** T12 no longer selects `repeat_delivered_statement`. The current router lets the exact question reach the interpretation boundary in the original state and after legitimate prints discovery. The offline fallback still asks which NPC the player means. Both replays preserve gameplay state, spend zero turns and ticks, and disclose no unsupported footprint fact.

The old fallback treated token overlap with the captain's patrol statement and a permissive answer-sufficiency result as enough to replay speech. The production change removes that fallback, tightens explicit and contextual speech cues, and keeps attribution tied to delivered, disclosable history.

The ownership matrix exercises established statement recall, speaker ambiguity, world questions, captured dialogue and inspection, and duplicate request identities. The supported captured NPC conversation still resolves the authored topic and lead. The wider consequence audit exposes existing legacy routing that spends a tick on an active-NPC scene question and on two attempts with unresolved addressees. Those controls bypass statement repetition.

The [regression report](REGRESSION_RESULTS.md) records suite counts and exact failure comparisons. The [consequence report](CONSEQUENCE_INTEGRITY.md) distinguishes read-only T12 from the separate fallback defects. Provider calls and spend were zero.
