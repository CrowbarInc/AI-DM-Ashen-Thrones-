## Deterministic acceptance for PR-PLAY-04

1. Real production start orchestration plus mocked SDK: valid structured opening delivered exactly, opening validation/adoption successful, latch true, turn/time/faction delta applied once, one dispatch.
2. Plain, truncated, malformed, authority-invalid and empty provider output: original reasons retained; no generic information answer sealed for scene_opening; return explicit failure, success false, started false, turn/time/factions and transcript success state unchanged from initialized baseline. Diagnostics may record an attempt without becoming a gameplay transcript row that blocks retry.
3. Provider exception, refusal/unknown usage and budget exhaustion: honest failure, no completed-opening telemetry, existing budget stop respected, initialization preserved. Never report an error fallback as initial_generation success.
4. Retry disabled: exactly one initial dispatch or zero on pre-admission refusal; no repair call, no silent budget restart or raised limit. Keep safe authority rejection; do not accept plain model output as repaired success.
5. Failure then valid explicit retry: one final committed opening/tick total, no replayed state mutations; duplicate after success returns 409 with zero changes/calls. Inject exceptions before and after preparation to cover the currently demonstrated partial rollback.
6. Verify canonical/public/log text agree and immutable seal only follows the applicable opening contract. A safe failure message is not successful narration, even if hard-valid as text.
7. Preserve authored initialization exactly, compare normal saves/frozen ATGB/experiments hashes; no new persistent gameplay state. Exercise unrelated-vocabulary opening fixture (for example harbor workshop) without Cinderwatch nouns in engine code. These are authored controls, not independent held-out evidence.
8. Focused regression: ordinary information inability, genuine clarification, social responses, non-social action outcomes, normal New Campaign reset and valid chat-triggered opening remain at their existing authority. No broad conversational/benchmark claim.

Six-request cap left five; no retries. `performance_analysis.json` separates all timing surfaces and reconstructed input contributors. Reconstructed preserved-seed request has 9,564 system characters and 96,588 user-payload characters: response_policy 21,236; instructions 14,433; decision 10,638; turn_packet 8,654; answer recipe 7,031; plan 6,757; scene 4,140. **Inferred:** instructions/policy and repeated projections dominate, not just campaign lore. These are character counts from current offline reconstruction, not original token attribution.

600 output tokens is a constrained budget for an envelope with declaration metadata plus sensory scene composition (and the requested legacy duplicate narration). Exact adequacy depends on returned text and claim count. Hitting the cap supports an incompleteness hypothesis but does not prove it. Structured contract has visible overhead, much of it carrying authority; unnecessary removable overhead is not demonstrated. C adds no required inference/token load and prevents a metered failure being mislabeled success; it does not promise fewer failures. No optimization, prompt/cap change or live test is part of this recommendation's implementation scope.
