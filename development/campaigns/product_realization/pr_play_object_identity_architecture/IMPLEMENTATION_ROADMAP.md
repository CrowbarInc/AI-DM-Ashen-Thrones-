# Phased implementation roadmap

Milestone: `pr_play_object_identity_architecture`. Every phase is a separate future authorized cycle; none begins here. Each preserves dirty inputs, uses isolated provider-free tests, hashes source/fixtures, updates NEXT_SESSION and produces a reviewable handoff. No unrelated cleanup, live provider calls, fixture rewrite, commit or push is implied. Module names not currently present are marked proposed.

## Phase 1 — Stable identity for existing singletons

Objective: core-generated instance ID/revision/provenance on explicitly migrated existing quantity-one inventory rows. Proposed `game/object_instances.py`; existing API import/bootstrap caller, defaults/importer/storage only where wiring requires; `state_authority.py` and its doctrine for narrow world_state character-object facet; dedicated identity tests. No gameplay resolver activation.

New contract: canonical reference, pure read, idempotent explicit migration, reject malformed migrated identity. Reuse character JSON, runtime scope and snapshots. Tests: duplicates of legacy item ID produce distinct UUIDs; reorder/rename does not alter them; repeated migration preserves bytes/IDs; legacy unknown fields preserved; stacks/invalid/cross-campaign collision rejected without writes; load/save and real snapshot restore preserve all identity fields; injected save failure restores prior file. Acceptance: existing inventory projections/actions unchanged and IDs durable. Migration: opt-in existing rows only, old saves readable; no attack-to-item creation. Dependency: none beyond current files. Risk: low–medium (allocation lifecycle and guard precision). T06 impact: identity foundation only, original refusal unchanged.

## Phase 2 — One validated marking on an established object

Objective: core service add_marking with supplied known content and established compatible material/surface in deterministic tests. Existing character host only. Modules: proposed instance owner; storage atomic character-save primitive; API staging and reuse of integrated_play.ordered_turn/client_request_id; state/schema contracts; narrow noncombat adapter and tests. Direct service tests first, no freeform T06 activation. Extend durable digest checks before cache return, with reset/restore namespace tests; do not invent another serialization lane.

New contracts: proposal, positive evidence, revision compare, explicit no-mechanics adapter decision, applied receipt and durable request dedupe ledger. Reuse ExplorationEngineResult, existing scope/snapshot and state guards. Tests: success exact text, stale revision/source/access/material, hidden source, unsupported operation, length bounds, retry key/digest conflict, no double cost, persistence failure and staged-memory discard, concurrent stale updates. Acceptance: one revision increment, one persisted marking and one safe receipt, no success before save; all unrelated behavior unchanged. Migration: optional markings on promoted records, no overwriting old keys. Dependency: phase 1. Risk: medium–high (transaction/publication seam). T06 impact: established-object mutation capability, no original-scenario claim.

## Phase 3 — Current inspection and removal

Objective: later exact inspection and compatible cleaning/removal. Modules: instance owner/read projection; exploration/referenced_surface integration; authorized_information/narration_authorization, mechanical_claims, schema_contracts/noncombat_resolution/ctir; player_http_projection and immutable publication seams only as necessary.

New contracts: visible current marking projection, remove_marking by ID, per-step outcome mapping. Reuse hidden/disclosure filtering, pre-seal closed-surface authority and immutable response. Tests: immediate/later inspection, exact source copy, changed source does not rewrite inscription, save/reload then inspect, cleaning removes current text, historical recall labelled past, hidden provenance absent, failed mutation never completed, seal/digest/pointer consistency, T04/T05/travel preservation. Acceptance: authoritative current inspection, no prompt-memory reconstruction or raw object leak. Migration: optional new read branch; unknown fields fail closed. Dependency: phase 2. Risk: medium–high (public allowlists). T06 impact: generic end-to-end controlled inscription demonstrated; original target/material still unresolved.

## Phase 4 — Equipment/part and mundane-evidence binding; T06

Objective: explicit clothing/part binding, material policy and semantic copy interpretation, then original T06 if actual state establishes prerequisites. Modules: proposed instance owner, intent_parser/player_interpretation_bridge, conversational_orchestration before unbound decline; local_interaction compatibility, bounded_improvisation controlled-fact policy; object-mechanics adapter and existing skill_checks as relevant.

New contracts: stable part selectors, generic equip relations, affordance evidence receipt, bound adapter version/result. Reuse visible target catalog, discovered knowledge, existing check machinery. Tests: language variants normalize to same operation; missing/short-sleeved/ambiguous clothing, dry corridor, inaccessible mud, incompatible surface, explicit wet mud trace, no fabricated ink/weapon/hidden text, cumulative resource abuse, exact known text and later cleaning, original unchanged twelve-turn HTTP scenario plus negative cases. Acceptance: truthful original T06 success only with positively established inputs; otherwise precise unresolved/refusal, no blanket success mandate. Migration: no automatic clothing mint from pronouns; explicit context promotion only. Dependency: phase 3. Risk: high (language/affordance boundary). T06 impact: first eligible original integration, conditional on factual prerequisites, no retcon.

## Phase 5 — Scene bindings, transfer and existing physical delegation

Objective: same instance survives custody/container/scene movement; migrate overlapping physical writes instead of duplicating them. Modules: proposed instance owner, world.py, storage runtime overlay bindings, API, physical_adjudication._objects/_write_props/_apply; noncombat/read projections as needed.

New contracts: one authoritative host, world-hosted records, cycle-free containment, atomic source/destination movement, binding migration/version and read-only index. Reuse scene_state/world_state guards and snapshot bundle. Tests: modified item transfer to NPC and scene then reload; wrong ownership/access blocked; duplicate host binding rejects; failed transfer leaves neither loss nor copy; old physical property copied once with provenance; migrated writer delegates; disabled gate stays disabled; T04 never grows position state. Acceptance: no shadow inventory and no competing open/placement states. Migration: explicit object-by-object; unmigrated experimental writers remain exclusive. Dependency: phases 1–4 contracts; no need to activate experiment to test delegation. Risk: high (cross-host invariants). T06 impact: inscription follows garment transfers/relocation.

## Phase 6 — Additional adapter capabilities and lifecycle operations

Objective: small separately scoped capabilities when product demand requires them (damage/repair, contents, attachment, electronic content, consumption). Modules: respective existing combat/conditions/skill owners plus instance service/adapter/content import seam. No universal crafting or physics engine.

New contract: operation-specific costs, failure effects, expiry and extension migration. Reuse identity/envelope/saves/inspection. Tests: at least three fake conceptual adapters, inert unknown extensions and ruleset switch preserving identity/markings; mechanical consumed resources and failure effects atomic; operation-specific ownership/hidden negatives. Acceptance: no PF fields in universal schema, unsupported capability fails closed, core identity unchanged. Migration: explicit versioned adapter maps, never infer compatibility. Dependency: phase 5 where cross-host effects needed, earlier instance seam otherwise. Risk: variable medium–high. T06 impact: none required for ordinary marking; specialized materials possible later.

Exactly one immediately recommended next executable cycle is phase 1, `pr_play_object_instance_identity`; all later phases are dependency planning, not concurrent authorization. A full ruleset loader, global import/reimport redesign, crash-atomic database, broad combat migration and comprehensive crafting remain deferred.
