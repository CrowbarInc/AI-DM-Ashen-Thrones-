## Preferred bounded combination

**A plus its tightly coupled B obligation in the existing production interpretation owner.** No parallel classifier, new call, broad PR-EG integration or host clarification veto. Keep the existing field vocabulary initially; make these distinctions explicit:

1. A correction of the preceding conversational subject/referent/description is a conversational CORRECTION, not evidence that the player is unintelligible. Preserve the corrected underlying request from supplied visible antecedents. Pending gameplay-intent revision remains represented by its existing action components and pending-state owner.
2. Reserve legacy CLARIFICATION for a genuinely missing choice/meaning/parameter. Explain how this differs from a player's clarifying their meaning and from NPC explanation requests; align purpose and mode instructions. For an unambiguous conversational correction, use existing OUT_OF_CHARACTER_CORRECTION mode with CORRECTION purpose and INTERPRETED status, correction.subject REFERENT when appropriate, no new operations. That legacy mode labels a nonexecuting table-level repair; the API already reconsiders its retained record before generic OOC text. Prove that route in deterministic tests before adopting it; do not assume changing the purpose alone fixes the mode.
3. For an answerable correction, select only supplied PUBLIC refs that support the **corrected underlying question**. Allow a bounded answer to supported portions when information is partial. No refs may be correct for a simple acknowledgment, genuine clarification or unavailable facts; absence is not globally forbidden.
4. Empty clarification_question is appropriate when no further information is needed. Genuine clarification should ask for the missing distinction, not reconfirm the correction verbatim. No new required reason enum is necessary for this first bounded experiment.

Existing `_communication_decision` already preserves selected evidence for CORRECTION after `_pending_revision_decision` abstains. However it currently joins evidence without acknowledging the correction. To meet the explicit acknowledgment-and-continuation requirement, a **small realization change in that same existing answer branch** is necessary if adopted: prefix a neutral acknowledgment for conversational CORRECTION answers after revision handling, without adding facts, model calls or semantic override. Do not put an acknowledgment into an evidence passage or treat model-authored subject prose as evidence. This is response realization, not Candidate C's clarification-necessity validation. Test both no-pending conversational correction and valid pending revision so the prefix cannot alter the mechanical guard's receipt.

The expected future behavior is acknowledgment plus public people descriptions; where evidence is insufficient, acknowledge and give a precise limitation or targeted question. A prefix alone, evidence-only routing, or changing the model label without checking final emission is not the repair. This is a small coupled contract/realization proposal, not evidence of a measured gain. Grade B reflects that uncertainty.

## Separately authorized live validation proposal

Preserve frozen ATGB v1 and its judgments byte-for-byte. Create new trial artifacts; do not overwrite original S08.2 or redefine its criteria. Run exact original “I meant the people, not the weather.”, independently repeat from the same isolated start, and rerun completed paraphrase “No, I was asking about the people, not the weather.” These are reproduction/related trials, not independent generalization.

Use a bounded declared matrix covering subject, referent and earlier-description corrections with and without sufficient public evidence; ambiguous correction; missing interlocutor; multiple plausible referents; missing action parameter; conflicting instructions; partial evidence; restricted evidence; and no-fact acknowledgment. Use independent held-out unrelated scenarios if claiming a general owner; keep exposed PR-EG/ATGB cases in their proper evidence level. A withheld trial must not be adapted after viewing it.

For each trial retain exact prior exchange, actual messages/schema, complete model JSON, evidence candidate and selected projections, adapter/host decision, final response, accepted/emitted equality, authoritative before/after snapshots, pending-intent status, provider ledger and errors. Score recognition, disposition, evidence selection, response adequacy and authority separately; mark human review UNREVIEWED until authenticated. A targeted limitation may pass only when actual missing information warrants it; merely restating the explicit correction as a question fails.

## Performance and acceptance

Expect **no extra admissions**, new classifier, retry, continuation or model switch. Keep the existing configured model/output limit unless separately authorized; verify complete responses rather than assuming room. Compare measured input/output/total tokens, instruction/context overhead, end-to-end and provider latency, actual retry settings and failed-call behavior against isolated historical trials. Predict no numeric savings or quality rate: selecting passages can increase output tokens, and acknowledgment adds a few host-produced words. Context enlargement is not required because the evidence is already present.

Acceptance separates deterministic contract/routing/authority PASS from original live adequacy, related variations, independent generalization and unrelated regression. No current full benchmark rerun is claimed. Stop on a material authority failure or new mode-routing conflict; preserve errors and do not automatically retry. Review the resulting evidence before further scope expansion.
