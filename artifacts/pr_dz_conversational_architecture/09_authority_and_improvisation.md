# Authority and Improvisation

Category A: established authoritative facts are protected by scene/world/session data, resolution contracts, GM-resolution decisions, and final-emission validators. Keep this model.

Category B: incidental description is supported through bounded incidental narration and prompt contracts. The problem is that conversational turns can be rejected before narration can use it. Incidental player posture should not become an executable component.

Category C: consequential improvisation has proposal/authority concepts in bounded improvisation and live resolution, but not a complete product lifecycle for proposing, validating, committing, persisting, and reusing new consequential facts during ordinary conversation.

Recommendation: keep authority gates for mutation. Let the orchestration layer distinguish non-persistent incidental narration, NPC claims as claim-only, consequential proposals requiring validation, and existing resolver-owned state changes.
