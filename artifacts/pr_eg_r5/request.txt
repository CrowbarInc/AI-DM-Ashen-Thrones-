# 1. CENTRAL QUESTION
# ============================================================
#
# Why does the engine repeatedly fail to understand
# and sustain ordinary conversation when its individual
# conversational mechanisms can pass focused tests?
#
# Investigate whether:
#
# - Player meaning is lost during interpretation.
#
# - Conversational intent is prematurely reduced to
#   deterministic command categories.
#
# - Multiple modules independently select the
#   addressee, subject, or relevant information.
#
# - Available authored facts are preferred over
#   actually relevant answers.
#
# - Answer sufficiency is evaluated too narrowly.
#
# - Conversational continuity is fragmented.
#
# - The AI has insufficient freedom to propose
#   harmless incidental conversation.
#
# - Defensive validation and fallback mechanisms
#   create conversational dead ends.
#
# - The pipeline's complexity itself contributes
#   to contradictory decisions.
#
# Test these hypotheses against source code and
# observed production behavior.
#
# Do not assume any hypothesis is correct.

# 3. NON-NEGOTIABLE ARCHITECTURAL CONSTRAINTS
# ============================================================
#
# Any proposed architecture must preserve:
#
# A. ENGINE AUTHORITY
#
# The engine remains authoritative for:
#
# - Canonical world state.

# - Time advancement.
# - Inventory and resources.
# - Consequential NPC commitments.
# - Authorized factual disclosure.
# - Persistence.
#

#

#
# C. INFORMATION INTEGRITY
#

# D. EPISTEMIC DISTINCTION
#

# E. PLAYER AGENCY
#
# The engine must not invent player actions,
# decisions, or consent.
#
# F. SIMULATION INTEGRITY
#
# Conversational flexibility must not bypass
# mechanics or authoritative state transitions.
#
# G. PERFORMANCE
#
# Avoid returning to enormous prompts and
# repeated provider retries.

# These constraints are not optional.

# 11. KNOWLEDGE SELECTION VS QUESTION RELEVANCE
# ============================================================
#
# Investigate why the engine repeatedly selects
# an authorized fact that does not answer the
# player's question.
#
# Example:
#
# PLAYER:
#
# "Who manages ferry schedules?"
#
# AVAILABLE FACT:
#
# "The bell beside the ferry is called the
# harbor bell."
#
# These share vocabulary and location context.
#
# They do not answer the same question.
#
# Determine whether current selection relies on:
#
# - Topic keywords.
# - Entity overlap.
# - Previously revealed information.
# - Resolver priorities.
# - Provider-selected facts.
# - Historical conversational recency.
# - Narrow answer-sufficiency rules.
#
# Propose how relevance and authorization
# could become separate explicit decisions.
#
# AUTHORIZATION:
#
# May the NPC disclose this information?
#
# RELEVANCE:
#
# Does this information answer the question?
#
# Both must be considered.
#
# ============================================================
