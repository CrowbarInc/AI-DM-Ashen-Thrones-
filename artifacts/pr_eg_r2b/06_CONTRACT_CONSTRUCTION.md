# 06 — Contract Construction

| Candidate | Assessment |
| --- | --- |
| Conversational authorization | Too early: establishes target and operation, not resolved knowledge; extending it into topic resolution duplicates R4 ownership |
| Social resolver | Owns selected topic/outcome; should provide evidence provenance, but should not absorb delivery/history formatting |
| Dialogue-authority layer | Already projects expression posture; useful integration surface, but must not discover new knowledge or repair authority gaps itself |
| Composition after resolver | Recommended: consume R4 authorization, selected social outcome, dialogue_authority and bounded prior speech once |

Inputs: established resolution contract, actual social payload, source references/revisions, already authorized public evidence and noncanonical continuity. Output: read-only generator projection plus host-only validation envelope. Build after topic/speaker resolution and before build_messages. Keep private disclosure policy and source validity out of generation where unnecessary. Missing/ambiguous source or speaker conflict means no factual grant; retain useful authorized subset or safe question/refusal.

The current resolver supplies topic id/text/clue linkage and target identity. _next_topic_to_reveal filters relevance/sufficiency and runtime reveal state, but does not preserve all epistemic/disclosure metadata. actual_resolver_packet shows both empty personal evidence and selected night_watch evidence without a new knowledge resolver. This supports a narrow evidence packet, not arbitrary knowledge questions. Production extensions would be provenance retention in existing structures, not a second world authority. Persist a bounded adoption summary; the full contract is turn-local unless needed for audit. Invalidate on source revision, target, question or disclosure change.

Evidence classes: STATIC = current source inspection; LOCAL = executed current production functions with disposable fixtures and external wire doubles; FRESH = new provider request; HISTORICAL = retained predecessor evidence; REPLAY = recombination of measured results; INFERENCE = proposed design; UNVERIFIED = not exercised. No fresh full-production API test was performed.
