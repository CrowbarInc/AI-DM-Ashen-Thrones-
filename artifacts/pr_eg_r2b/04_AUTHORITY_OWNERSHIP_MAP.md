# 04 — Authority Ownership Map

| Authority | Existing owner and evidence | Contract responsibility |
| --- | --- | --- |
| Action | ordinary_semantic_ownership / resolution_contract; conversational orchestration; pre-tick gate in api | Consume executable operation and existing interaction id |
| Speaker | assess_addressee_grounding, social speaker grounding | Match canonical npc_id, target and ownership; never promote provider candidate id |
| Knowledge | authored NPC topics/knowledge, clue knowledge, runtime revelation; social resolver selection | Project only selected, speaker-valid, disclosure-authorized evidence |
| Expression | dialogue_authority, dialogue_social_plan, prompt_context; validation/adoption pipeline | Bound paraphrase, incidental scope and response behavior; generator owns wording only |
| Commitment | resolver-owned game outcomes; dialogue_authority noncanonical memory is separate | New binding offer/promise requires explicit resolver result; memory cannot grant an obligation |
| World | social/noncombat/domain resolvers, world tick and approved state updates; storage only I/O | Speech cannot mutate canonical state or authorize model world_updates |

The knowledge owner is distributed across existing authored/runtime structures, not a general-purpose NPC knowledge oracle. There is no fully typed factual/belief/rumor/deception grant in the selected-topic output. Explicit permission flags alone do not create such knowledge. Preserve that gap rather than claim full readiness. A successful social check licenses only its actual selected outcome. Opinion posture cannot create a faction relationship.

Evidence classes: STATIC = current source inspection; LOCAL = executed current production functions with disposable fixtures and external wire doubles; FRESH = new provider request; HISTORICAL = retained predecessor evidence; REPLAY = recombination of measured results; INFERENCE = proposed design; UNVERIFIED = not exercised. No fresh full-production API test was performed.
