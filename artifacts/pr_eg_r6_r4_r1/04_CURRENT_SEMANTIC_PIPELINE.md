# 04 — Current Semantic Pipeline

Ordinary NPC topic prose enters `_topic_rows` (game/unified_semantic_planning.py:665). Host disclosure policy gates candidate text. `_provider_context`:422 compacts visible sources/history; `_invoke_provider`:460 jointly proposes request and up to four source propositions using open predicate/role names. `clean_proposition` validates schema; witnessed/roles_witnessed require literal evidence and host-known aliases. `coverage` and `named_coverage` compare predicate names, role names/values, negation, scope and epistemic status deterministically. Sufficiency depends on the requested role being present. `authorize_information_turn`:782 binds host-owned conversational references and rechecks source eligibility; final delivery is sealed by game/immutable_valid_response.py.

Only interpretation needs a provider call; eligibility, syntax, correspondence, sufficiency, authorization and sealing are host stages. Predicate/role names remain AI proposals. Exact names, missing values and epistemic mismatch reject valid evidence; literal anchors cannot prevent wrong role labels or epistemic strengthening. A runs the production prompt/schema/coverage kernel with captured transport, not the full API, routing, authorization or emission pipeline.
